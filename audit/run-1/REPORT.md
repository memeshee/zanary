## 2. Security posture summary

The repository's own claim is unusually strong — a privacy claim published as a re-derivable, expiring artifact — and the audit found no break in the cryptographic core's binding model. What it found instead is a cluster of *boundary and bookkeeping* defects in the code that is supposed to enforce and record authority: the bounded payer's grant does not bound what a merchant channel can cost or repeat; the offline verifier that a stranger is told to run can be made to abort instead of returning a verdict, and its claims/body agreement test is substring containment; and the CI gate that turns a run into a green build accepts a skip-decided run as "every property held". Three medium findings are reachable through ordinary inputs (a grant written with a timezone offset, a re-sent invoice, an invoice priced at one zatoshi), one medium finding is a code-execution sink in the published composite action for consumers who template its inputs, and the remaining low findings are panic-instead-of-diagnostic defects and unbounded intake on same-principal paths. The strongest positive pattern is the property library itself and the `policy-downgrade` / `report-leak` detectors — they bite on honest fixtures — plus the sandboxable, offline test surface, which is what let this run reproduce most of the above without touching the rig.

### Composite action expands caller-supplied with: inputs into shell script text
